# Product stories

One file per feature or fix, written before engineering picks it up. Each story uses the same five sections: **Problem**, **User story**, **Acceptance criteria**, **Open questions**, **Out of scope**.

Stories are written in the vocabulary of an Obsidian user (notes, vault, commands, settings), stay under about 120 lines, and always spell out three things: the explicit user action plus undo path for anything that changes a note, when note content leaves the vault for an AI provider, and which steps are desktop-only (yt-dlp, ffmpeg).

A story is a spec, not a plan. Decisions that change it are recorded in `DECISIONS.md`; the tracking issue links back here.
